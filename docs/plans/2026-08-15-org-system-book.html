Implementation plan · ready to build

Pavo + Hyper + GBrain, on SQLite

Repo: OpenFlyWheel Store: SQLite + FTS5 Dogfood: Arceus-Inc org

One company workspace. Many locked systems. GitHub and agents write evidence in. Extractors propose. You verify. Agents read a packet with gaps. No wiki, no dream cycle, no tournament.

The combo

Pavo Truth Lock systems. U1–U7. What+How gold. SaO. Artifact-correct can still be system-wrong.
Hyper Write path Admit, don’t mirror. Immutable episodes. Typed edges. Agents in and out.
GBrain Org shape Workspace ⊥ source ⊥ boundary. Gaps on every packet. Frozen verbs. Fail-closed remote.
Not a GBrain fork SQLite is the system of record — not a markdown git vault. The coding agent does not write gold. There is no LLM on the v0 read path. Person/company/deal types stay out.

Three axes

--workspace   which company SQLite file
--source      which connector / repo inside it
--boundary    which locked production system

Arceus-Inc is one workspace. Onboarding may lock several systems in the manifest only. Those names never appear in reusable code or generic tests.

Org coverage = macro-average of each boundary’s U1–U7 coverage. A fat U3 on one repo cannot hide empty U7 on another.

SQLite is the book

One file per workspace: ~/.openflywheel/<id>/book.sqlite. WAL, foreign keys, migrations. FTS5 over claims + episodes with ACL stored for prefilter.

Tables: workspaces, identities, boundaries, sources, episodes, evidence_anchors, proposals, claims, edges, why_probes, coverage_requirements, checkpoints, agent_sessions, pins, audit_rejects.

Export can write compiled markdown for humans. Re-import is not disaster recovery. Recovery is the DB + pins.

Frozen book verbs

CLI and MCP are the same ops. Additive-forever, like GBrain MEMORY_VERBS — but no synthesize.

Write and read

Write — Hyper inside Pavo

Source → admit → episode → OFW extractor (SaO, then grounded job, then expert) → proposal → you verify → claim. History never deleted.

Read — deterministic

Identity + ACL first. Active claims at pin. FTS5. Direct edges only. Packet = compiled claims + episode timeline + gaps. No LLM.

Waves — stop at each gate

A · Skeleton

Package, contracts, SQLite, ofw workspace init.

Gate: pytest creates a temp DB and reads a workspace. No network.

B · Onboard and lock

Staged onboard. Locate on a fixture repo. Human locks many boundaries.

Gate: two locked boundaries. Extract without lock is refused.

C · GitHub + episodes

Admit, hash idempotency, checkpoint after episode txn only.

Gate: ingest twice → same ids. Failure leaves checkpoint still.

D · SaO proposals

U3/U4 from config, deps, schemas, tests. Anchored. No U5–U7 fiction.

Gate: proposals exist; claim table still empty.

E · Verify, edges, coverage, pins

Promote. Tension. Org macro-average. Pin immutability.

Gate: later ingest cannot change a pin. Coverage ignores raw count.

F · Packet

book_context. Two identities, two packets.

Gate: no unverified Why. Gaps match coverage.

G · Agents

Claude Code + Cursor installers. Background worker proposes only. MCP verbs.

Gate: session → episode, not claim. MCP equals CLI.

H · Dashboard + Arceus-Inc dogfood

Read-only U1–U7 UI. Expert notes. Manifest names the stack; core code does not.

Gate: cross-repo question answered from a packet; U5–U7 holes visible.

Steal / leave

In

  • Locate/lock, U1–U7, SaO
  • Admit → episode → proposal → verify
  • Workspace ⊥ source ⊥ boundary
  • Gaps on every packet
  • Frozen verbs, fail-closed remote
  • Greplica-shaped installers

Out

  • Markdown vault as SoR
  • Dream auto-apply
  • LLM synthesize on read
  • Agent-written proposal files
  • Slack / Gmail / Notion in v0
  • pgvector, tournament, people CRM
