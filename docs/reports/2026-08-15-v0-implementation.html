OpenFlyWheel v0 — Waves A through H

Evidence-based report for the first shippable System Book foundation: Pavo truth discipline, Hyper write path, GBrain org topology habits, SQLite as system of record.

Version: 0.1.0 Python: 3.11+ Report date: 2026-08-16 Author: Composer 2.5 (doc-updater)

⚠ Not committed · Not pushed — implementation exists on disk only. Last git commit: 08e987c (design doc only). All src/, tests/, and this report are untracked or unstaged.

1. Executive outcome

Verdict v0 delivers an offline-capable, typed Python application (ofw) that onboards a company workspace, locks production-system boundaries, ingests GitHub fixture evidence and agent sessions into immutable episodes, extracts SaO proposals (U3/U4), verifies claims under human authority, serves deterministic ACL-filtered retrieval packets, and exposes the same book verbs over CLI and MCP stdio — with an opt-in real-environment harness proving read-only safety on live Cursor config and Arceus checkout.

Pavo truth

Seven Essential Truths (U1–U7). What + How are gold; Why is a probe only. Locate → lock before extraction. Claims require evidence anchors, authority, and verification. Pins are immutable snapshots.

Hyper write path

Source → admission → immutable Episode → SaO/background extractor → ClaimProposal → human verify → active Claim. History preserved via edges (derived_from, in_tension_with, supersedes). Agents are bidirectional surfaces, not claim writers.

GBrain habits

Three axes: Workspace ⊥ Source ⊥ Boundary. Gap-on-every-packet. Compiled packet + episode timeline as views. Frozen verb protocol (8 book ops). Fail-closed ACL. SQLite SoR — not a markdown vault.

5. Typed contracts and OperationResult

All domain models live in src/openflywheel/contracts/ as frozen Pydantic v2 models with NewType IDs (WorkspaceId, ClaimId, etc.). No typing.Any in service or repository APIs.

class OperationResult(BaseModel, Generic[T]):
    status: OperationStatus          # success | warning | error
    summary: str
    next_actions: tuple[str, ...]
    artifacts: tuple[str, ...]
    data: T | None
    error: OperationError | None     # code, message, root_cause_hint,
                                     # safe_retry, stop_condition

render_json() produces harness-compatible recovery output. CLI and MCP both emit this envelope. Errors are typed — e.g. VERIFY_UNAUTHORIZED, GET_ACL_DENIED, PROPOSE_ANCHOR_NOT_FOUND, MCP_UNKNOWN_TOOL.

dict is quarantined to raw JSON/library boundaries (pydantic_json.py, MCP stdio argument parsing) and converted immediately via TypeAdapter. Third-party stubs live in typings/ (mcp, typer, fastapi, uvicorn, sqlite3) — honest partial coverage, not full runtime types.

6. SQLite schema, migrations 001–005

MigrationContents
001_foundation.sqlCore tables: workspaces, identities, boundaries, sources, episodes, evidence_anchors, proposals, claims, edges, coverage_requirements, checkpoints, agent_sessions, pins, audit_rejects, onboarding_runs
002_episode_idempotency.sqlUnique index (source_id, external_id, checksum) on episodes; dedupe index on audit_rejects
003_book_core.sqlProposal status + idempotency key; claim provenance; FTS5 claim_fts virtual table
004_book_hardening.sqlPin snapshot tables (claim/anchor/edge); immutability triggers; FTS sync triggers; proposals strict NOT NULL boundary
005_agent_surfaces.sqlbackground_jobs queue with lease fields; unique agent_sessions per platform+ref

Engine settings

  • PRAGMA foreign_keys = ON
  • PRAGMA journal_mode = WAL
  • PRAGMA busy_timeout (default 5000 ms)
  • Parameterized SQL only in repos

Unit of Work

IngestUnitOfWork.commit_episode_bundle writes episode + anchors + checkpoint in one transaction. AbortCheckpointCommitHook tests prove zero partial rows on failure. Verify uses separate VerifyUnitOfWork.

Pin snapshots: book_pin copies claim text, anchors, and edges into immutable snapshot tables. Triggers abort UPDATE/DELETE. Pinned reads use snapshot rows, not live mutable claims.

FTS: Triggers index only active claims (state='active' AND valid_to IS NULL). ACL JSON stored UNINDEXED; pre-filtered before LIMIT.

7. Onboarding, GitHub, admission, idempotency

  • Staged onboard: onboarding_runs tracks connect → locate → lock with monotonic stage advancement (onboarding/stage.py).
  • Locate: deterministic scan (pyproject.toml + src/ heuristics). LLM cannot lock.
  • Lock: versioned BoundaryManifest with shape, owners, KPI, authorities, exclusions. Extraction refused until lock.
  • GitHub: FixtureGitHubClient for offline ingest; live.py stub behind OFW_GITHUB_TOKEN (@pytest.mark.live_github).
  • Admission: secrets, junk, excluded paths → audit_rejects without body. Locked manifest exclusions merged with CLI --exclude (ingest/scope.py).
  • Idempotency: (source_id, external_id, checksum) unique on episodes; proposal idempotency keys for transcript extraction.
  • Checkpoint: advances only inside successful episode transaction; unchanged on injected failure (test_atomic_writes.py).

  • cursor_transcript.py / claude_transcript.py — role normalization
  • episode_record atomic: episode + session + background job
  • correction_record — new episode + proposal against claim
  • Recursion guard via background_scope()

MCP stdio (actual subprocess)

ofw serve --surface verbs --home /path/to/workspace-home

stdio_runner.py uses mcp_types SDK. test_mcp_stdio.py spawns real subprocess, lists exactly 8 tools, calls book_context, verifies parity with direct McpBookServer. Unknown tool hidden_op returns is_error=True.

Background worker

BackgroundWorkerService acquires 30-second lease, processes TRANSCRIPT_EXTRACT jobs, retry with max attempts. Proposal detector mirrors regex in e2e helpers.

15. Limitations (honest)

  • GitHub ingest uses local FixtureGitHubClient, not live API in default tests
  • Arceus e2e bounded to 50-file copy; 500-file hash inventory (not full tree)
  • Transcript selection deterministic (sorted paths, OpenFlyWheel/Arceus preference) but content varies by machine
  • No kernel-level write guard — safety is hash inventory + temp paths only
  • SaO breadth limited to deterministic code/config patterns; no autonomous LLM extraction in v0
  • Dashboard is local loopback read-only; not a deployed service
  • Real global Cursor ~/.cursor/hooks.json schema not yet adapter-supported — project-local hooks only
  • Grounded LLM extraction job stubbed; expert U2/U5/U6/U7 gaps remain questions, not fabricated claims
  • Codex and OpenClaw connect stubs only — Claude Code + Cursor fully wired in Wave G
